# Сирин

Публичный сайт и система управления контентом хореографического ансамбля «Сирин».

Проект является единым Next.js-приложением:

- публичный сайт — `/`;
- административная панель — `/admin`;
- JSON API — `/api`;
- база данных — SQLite через Prisma;
- изображения — `public/uploads`;
- письма о новых заявках — SMTP.

## Требования

- Node.js 20.19 или новее;
- npm 10 или новее.

Docker для локальной разработки не требуется.

## Локальный запуск

```bash
npm ci
npm run db:setup
npm run dev
```

После запуска:

- сайт: http://localhost:3000
- админка: http://localhost:3000/admin

Локальные логин и пароль берутся из `ADMIN_EMAIL` и `ADMIN_PASSWORD` в `.env`.
Значения по умолчанию предназначены только для разработки и заблокированы production-проверкой.

Если `.env` отсутствует, скопируйте `.env.example` в `.env` и заполните его.

## Возможности админки

- новости: создание, черновики, публикация, дата, обложка 1230×692, форматированный текст и галерея;
- команда: карточки, фото, баннер, образование, стаж, достижения, галерея и ручной порядок;
- заявки: список, почтовый статус, рабочий статус и удаление;
- главная карусель: загрузка фотографий, включение/выключение и порядок.

Загружаемые изображения преобразуются в WebP. Обложки и фотографии карусели автоматически обрезаются до нужного формата.

## Почта

Для Mail.ru создайте отдельный пароль приложения и заполните:

```dotenv
APPLICATION_RECIPIENT="ef.sirin@mail.ru"
SMTP_HOST="smtp.mail.ru"
SMTP_PORT="465"
SMTP_SECURE="true"
SMTP_USER="адрес-отправителя@mail.ru"
SMTP_PASSWORD="пароль-приложения"
```

Если SMTP не настроен, заявка всё равно сохраняется в базе. В админке она получает почтовый статус `SKIPPED`.

## Публичный API

- `GET /api/news?count=12&start=1`
- `GET /api/news/{id}`
- `GET /api/crew`
- `GET /api/crew/{id}`
- `GET /api/contacts`
- `GET /api/reviews`
- `GET /api/home`
- `GET /api/home-slides`
- `POST /api/courses`

Старые форматы ответов сохранены, включая `pre_images`, `photo`, `banner` и вложенный массив отзывов.

## Развёртывание на VPS

Перед первым запуском на сервере:

1. Установите Docker и Docker Compose.
2. Привяжите домен к IP сервера.
3. Оставьте публичные URL same-origin: `NEXT_PUBLIC_STATIC_URL="/"` и `NEXT_PUBLIC_API_URL="/api/"`.
4. Установите новый `AUTH_SECRET`, новый пароль администратора и `COOKIE_SECURE="auto"`.
5. Настройте SMTP.
6. Выполните:

```bash
docker compose up -d --build
```

## Ветки и выпуск в production

- `dev` — рабочая ветка. Все изменения и обычные push выполняются сюда.
- `master` — только проверенные production-релизы.
- VPS проверяет `master` раз в минуту и автоматически разворачивает новый коммит.
- `.env`, SQLite-база, uploads и backups при деплое сохраняются и никогда не берутся из Git.

Обычная работа:

```powershell
git switch dev
git add <файлы>
git commit -m "Описание изменения"
git push
```

Выпуск проверенной версии:

```powershell
.\scripts\release.ps1
```

Скрипт обновляет `dev`, запускает тесты и production build, выполняет fast-forward
`master`, отправляет его на GitHub и возвращает локальную рабочую ветку на `dev`.

Контейнер при запуске проверяет production-настройки, применяет миграции и создаёт администратора.
Каталоги `data` и `uploads` подключаются как постоянные тома и не теряются при пересборке.

В compose используется Caddy: он слушает порты 80/443, перенаправляет запросы в Next.js и автоматически выпускает/обновляет HTTPS-сертификат после того, как A/AAAA-записи домена указывают на VPS. IP-адрес сервера доступен по HTTP для первичной диагностики.

## Резервные копии

В резервную копию должны входить одновременно:

- `data/sirin.db`;
- каталог `uploads`;
- production `.env` в защищённом хранилище.

Перед копированием SQLite-базы рекомендуется кратковременно остановить контейнер приложения либо использовать штатную SQLite-команду `.backup`.
